# Russian quality pass (2026-11-12): brief for every Russian editor

The Aerospace Knowledge Hub (`/Users/noone/code/aerospace`) is bilingual: every visible English string has a Russian twin
(`data-ru` attributes; script-drawn text through `T('English','Русский')`). The Russian was mostly machine-written and has
never had a native read. Since 2026-10-28 the Russian also has its own URLs (`/aerospace/ru/<slug>`), so search engines and
Russian readers now see it on its own. This pass makes it read as if a careful Russian science editor wrote it.

## Read first
- `CLAUDE.md` (repo) and `_tools/README.md` (how pages are built), `_tools/RU-STYLE.md` (the house style and glossary —
  written by the lead editor; follow it exactly; if something is missing, decide by the majority usage on the site and add
  a line to the "Proposed additions" list in your report, don't edit RU-STYLE.md yourself unless you are the lead).
- `node _tools/ru-audit.js <slug>` lists English still visible on a Russian page (run it before and after).

## Where the Russian lives
- **Generated guides** (folder `_tools/articles/<slug>/` exists): edit `body.html` (`data-ru`, `data-aria-ru`), `script.js`
  (second argument of `T(...)`, `ru:` fields of data and references), `meta.json` (RU title/labels). Then
  `cd _tools && python3 assemble.py articles/<slug>` and `./check-all.sh <slug>`: everything except a DRIFT line must be clean
  (DRIFT is expected site-wide: other scripts add blocks after the build). Never edit the generated root page by hand.
- **Hand-made guides** (no article folder): edit the root `<slug>.html` directly (its `data-ru` attributes, its scripts' RU
  strings). If `_tools/handmade/<slug>/checks.js` exists, run `./check-all.sh <slug>` and keep it clean.
- Never edit `ru/` (generated by the coordinator with `_tools/ru_pages.py`), `pages.json`, `index.html`, `related.json`,
  `assets/`, other editors' guides, or git (no commits, no stash, no checkout).

## What to do on each guide
1. **English left in Russian mode** (from ru-audit and by reading): chart labels, legends, table cells, button and slider
   labels, `aria-label`s, status lines, HUD labels, alt text. Add the Russian twin the way the page already does it (data-ru,
   T(), or a data attribute the script reads). Proper names that are written in Latin in Russian too (NASA, InSight, GRAIL,
   SEIS) stay Latin per RU-STYLE.
2. **Native edit of every Russian string**: grammar, cases and agreement, word order, natural technical Russian (no calques),
   terminology per the glossary, typography (« », —, non-breaking spaces before units and after initials, decimal comma,
   thin-space thousands as the style says), consistent mission and person names. Keep meaning identical to the English —
   never add, drop or soften a fact. Numbers must match the English exactly (and the script's computed values).
3. Keep markup intact: quotes inside attributes must stay escaped (`&quot;` or typographic « »), never a raw `"` inside a
   `data-ru="…"` value (it breaks the attribute — the test reports brokenAttrs). Keep `<sup>`, `<sub>`, `[n]` citations, `&amp;`.
4. If an English sentence itself is wrong or unclear, don't fix the English: note it in your report.

## Report back (concise)
Per guide: strings edited (approx.), English leftovers fixed (ru-audit before → after), any check status, open questions.
Then: proposed glossary/style additions, English problems noticed, anything you could not do.

  bilingual in the build) and a `data-phase-ru="…"` next to every `data-phase="…"` in body.html (the HUD picks it in RU mode).
  Hand-made guides: follow what the lead did on `viking.html` and `transfer-earth-to-mars.html`.
- **Numbers.** helpers.js now formats Russian integers like the style: no grouping below 10 000, a no-break space from
  10 000 up. Make text numbers match (1524, 10 000). Generated guides pick this up when you reassemble.
- **Reference examples** to imitate: `transfer-earth-to-mars.html`, `viking.html` (hand-made) and
  `_tools/articles/relay-telstar-syncom/` (generated), all edited by the lead.
- One known flaky check: MASCON's "piece … far below a frame budget" timing check can fail when the machine is busy. If that
  is your only FAIL and it is on mascon-grail-lunar-gravity, rerun once; report it if it still fails.
