# Aerospace Knowledge Hub

Bilingual (EN/RU) aerospace & space-science field-guide site: a large set of single-file HTML articles (missions, programs, telescopes, physics/logic/music-theory field guides) plus an index, sitemap, and `llms.txt`.

## Structure
- One `.html` file per article at repo root, static and dependency-free. Newer guides are generated from `_tools/articles/` and committed; older ones are hand-authored.
- `assets/` — shared site CSS/JS used across articles.
- `_tools/` — sources + build/test tooling for the generated guides (Wave 1 onward): `articles/<slug>/` sources, `assemble.py`, `build-site.py`, `check-all.sh`, `shot.sh`. Edit the sources, not the generated page; see `_tools/README.md`. Underscore keeps Jekyll from publishing it.
- `index.html`, `pages.json`, `sitemap.xml`, `llms.txt` — site manifest/navigation, generated by `_tools/build-site.py` (see the last section); never hand-edit.
- **Search + See also** (2026-10-22): `assets/site.js` adds a Search dialog (button, `/`, Ctrl/Cmd+K; EN/RU, folds case/accents/ё) over pages.json + `search.json` (generated by `_tools/build-site.py`), and a "See also" block at the end of every guide from `related.json` (generated from the `related` list in each guide's `meta.json`; `build-site.py` fails if a guide has fewer than 3).
- **Freshness register** (2026-10-22): `_tools/freshness.json` (page, claim, source, review_by; generated from the `freshness` rows in each guide's `meta.json`); `.github/workflows/freshness.yml` opens/updates one issue monthly for overdue rows.
- **Mission of the day** (2026-10-15): `assets/mission-of-day.js` is the canonical widget (129 missions 1957–2025 with EN + RU name/line, WebGL2 schematic-trajectory shader, "Today" = nearest anniversary in UTC, period chips + ‹ ›). Used by the `#mission-of-day` section under the hero of `index.html` (markup + CSS inline there, monochrome via `--ae-acc` on `.mod-frame`) **and** by the followorbounce.github.io homepage, which loads this same file from `/aerospace/assets/` (its markup lives in that repo's `engine/aero-shader.{html,css}`). The script only needs the `ae-*` ids; text follows `<html lang>` (en/ru) live; dark tones only when the frame background is dark. When adding a guide for a mission, set its slug here (by hand; `build-site.py` reports `MOD.json` rows that are missing). Test hook: `window.__aePreserve=true` before the script, then `__aeShow(i)`, `__aeSetP(p)`, `__aeDraw(ms)`; headless Firefox only captures the canvas after `toDataURL()` into an `<img>`.
- `AGENTS.md` — the full "virtual expert team" charter (engineering, science, content, workflow roles). Read it before nontrivial changes; it has authority over role-specific conventions this file doesn't restate.
- `docs/`, `time philosophy/` + `time-philosophy/` (duplicate-looking dirs — check both before assuming one is dead) — secondary content areas.
- A few stray root files look like abandoned duplicates/typos (`build-your-own-cubsat.html`, `ISSandMir.html`, `lagrange-points.html`, `unfold-james-webb.html` vs. their differently-named full versions) — don't edit these without checking `pages.json`/`sitemap.xml` for which one is actually live.

## Conventions
- Single-file-per-article pattern; keep bilingual EN/RU markup structurally parallel so shared CSS/JS keeps working for both.
- No framework/build-step creep without explicit sign-off (see AGENTS.md, Principal Frontend Engineer role).
- WCAG 2.2 AA+ accessibility, responsive/fluid layout, progressive enhancement.
- Never use Russian in code/UI/docs unless the task explicitly calls for it (bilingual EN/RU *content* pages are the one deliberate exception the site's premise calls for).

## Share pictures (og:image)
Added 2026-10-28. Every public page has a 1200×630 share picture at `og/<canonical path>.jpg` (`og/index.jpg` for the front page) and the tags `og:image` (+ width, height, alt), `twitter:card` = `summary_large_image` and `twitter:image`. `_tools/assemble.py` writes the tags for generated guides; hand-authored guides carry them directly, placed after the page's other og:/twitter: tags. The pictures are drawn by `engine/og_cards.py` in the followorbounce.github.io repo (one card template, this site's own palette and type, `og/manifest.json` = a hash per card so unchanged cards are skipped). After adding or renaming a page, or changing a title or description, run `python3 engine/og_cards.py aerospace` from that repo; it renders new cards, adds missing tags and deletes cards of pages that went away. `--check` lists pages without tags.

## Structured data (2026-10-28)
Every guide carries `Article` + `BreadcrumbList` JSON-LD between `<!-- fob-ld -->` markers, written by `engine/structured_data.py` in the followorbounce.github.io repo (headline = English half of the title, dates from git). `_tools/assemble.py` rewrites whole pages, so run `python3 engine/structured_data.py aerospace` there after assembling a guide.

## Russian edition (2026-10-28, reach plan F6)
Search engines only indexed the English text (the Russian lived in `data-ru` attributes behind the EN/RU toggle). Now every guide and the index also exist at `/aerospace/ru/<slug>` (`ru/<slug>.html`, `ru/index.html`), **generated** by `python3 _tools/ru_pages.py` (build-site.py runs it; run it yourself after editing a hand-authored guide; `--check` lists stale pages; never edit `ru/`). It does at build time what each page's `applyLang('ru')` does (outermost `[data-en][data-ru]` innerHTML := data-ru), sets `<html lang="ru" data-edition="ru">`, Russian title (pages.json label + site title) / description (hero lede) / og tags, a self canonical, hreflang en/ru/x-default on both editions (`<!-- hreflang -->` block in the English page), and points `/aerospace/<slug>` links at the edition. `assets/site.js`: on `data-edition` pages it clicks the page's own RU button once (script-drawn labels follow) and ignores the saved preference; navigation/See also/search links stay in the edition (`href()`); on any page with both alternates the EN/RU toggle navigates to the other URL (keeping `#hash`) instead of swapping in place. Edition pages get their own share cards (`og/ru/…`) and JSON-LD from the followorbounce.github.io scripts (run `engine/og_cards.py aerospace` and `engine/structured_data.py aerospace` after regenerating). `sitemap.xml` (written by `build-site.py`) lists both URLs of every guide with `xhtml:link` alternates. Known gap: a few HUD labels come from English-only data attributes (also English in the old in-page Russian mode).

## Shared blocks, dates and checks (2026-11-14, supersedes the notes above where they differ)
- **This repo owns its injected blocks.** `_tools/blocks.py` writes hreflang, the analytics tag, JSON-LD and the network footer in fixed slots (`place()`); `assemble.py` (generated guides), `ru_pages.py` (Russian edition, including its own og tags) and `finalize.py` (hand-made pages) call it. The followorbounce.github.io scripts no longer write to this site's pages: `engine/og_cards.py aerospace` only renders share pictures (Firefox, or Chrome via `BROWSER=chrome`), `engine/structured_data.py` skips this site.
- **Dates** in JSON-LD come from `_tools/dates.json`, never git. After changing a guide's content: `python3 _tools/finalize.py --touch <slug>` (sets "modified" to today, and "published" for a new guide), then `python3 _tools/ru_pages.py`.
- **A clean rebuild is byte-identical.** `bash _tools/check-all.sh` covers every guide in pages.json (generated: rebuild + drift + numeric checks; hand-made with checks; smoke test for the rest), enforces citation numbers against reference counts, and runs the whole-site checks (`finalize.py --check`, `ru_pages.py --check`, `build-site.py --check`, `site-check.py`). It must end in `ALL OK`; DRIFT is now always a real problem. `.github/workflows/check.yml` runs it on every push and pull request.
- `ru_pages.py` and `finalize.py` rewrite a page only when its bytes change, so a one-guide edit touches that guide and its Russian twin only.
- Shared guide CSS is `_tools/base.css` (no longer read live from the Mirrors & Dishes page). `assemble.py --og` renders the share picture; authors never pass it.
- `_tools/shot.sh <slug> [width] [height]` starts its own server and works with Chrome (phone widths are shown in an iframe; the picture is 500 px wide with the page on the left).
- **One manifest per guide, one command (E3).** A guide's codename, labels, llms.txt line, related guides and freshness rows live in its `meta.json` (`_tools/articles/<slug>/` for generated guides, `_tools/handmade/<slug>/` for the rest); `_tools/site.json` holds the site block, external links and the categories with their guides in display order. `python3 _tools/build-site.py` writes `pages.json`, the lists between the `<!-- guides: … -->` markers in `index.html`, `llms.txt` (from the first `## `), `related.json`, `_tools/freshness.json`, `search.json` and `sitemap.xml`, then runs `ru_pages.py`. Never edit those files by hand; `build-site.py --check` is part of `check-all.sh`.
- **Adding a guide:** fill the manifest, add the slug to its category in `site.json`, `python3 _tools/finalize.py --touch <slug>`, `python3 _tools/build-site.py`, `bash _tools/check-all.sh`. `wire.py` is retired (it only prints these steps).
- **The sitemap is committed with the change.** `.github/workflows/sitemap.yml` is gone, so no bot commit lands after a push; `check.yml` fails if `sitemap.xml` (or any other generated file) is stale.
- `assets/mission-of-day.js` stays hand-edited (the followorbounce.github.io homepage loads it); `build-site.py` only reports `MOD.json` rows that are not in it.
