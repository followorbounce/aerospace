# Aerospace Knowledge Hub

Bilingual (EN/RU) aerospace & space-science field-guide site: a large set of single-file HTML articles (missions, programs, telescopes, physics/logic/music-theory field guides) plus an index, sitemap, and `llms.txt`.

## Structure
- One `.html` file per article at repo root, static and dependency-free. Newer guides are generated from `_tools/articles/` and committed; older ones are hand-authored.
- `assets/` — shared site CSS/JS used across articles.
- `_tools/` — sources + build/test tooling for the generated guides (Wave 1 onward): `articles/<slug>/` sources, `assemble.py`, `wire.py`, `check-all.sh`, `shot.sh`. Edit the sources, not the generated page; see `_tools/README.md`. Underscore keeps Jekyll from publishing it.
- `index.html`, `pages.json`, `sitemap.xml`, `llms.txt` — site manifest/navigation, regenerate together when adding a page.
- **Search + See also** (2026-10-22): `assets/site.js` adds a Search dialog (button, `/`, Ctrl/Cmd+K; EN/RU, folds case/accents/ё) over pages.json + `search.json` (generated by `_tools/search-index.py`), and a "See also" block at the end of every guide from `related.json` (hand-edited; the one place those links live). `wire.py` regenerates search.json and fails loudly if related.json is missing the new guide.
- **Freshness register** (2026-10-22): `_tools/freshness.json` (page, claim, source, review_by); `.github/workflows/freshness.yml` opens/updates one issue monthly for overdue rows.
- **Mission of the day** (2026-10-15): `assets/mission-of-day.js` is the canonical widget (108 missions 1957–2024 with EN + RU name/line, WebGL2 schematic-trajectory shader, "Today" = nearest anniversary in UTC, period chips + ‹ ›). Used by the `#mission-of-day` section under the hero of `index.html` (markup + CSS inline there, monochrome via `--ae-acc` on `.mod-frame`) **and** by the followorbounce.github.io homepage, which loads this same file from `/aerospace/assets/` (its markup lives in that repo's `engine/aero-shader.{html,css}`). The script only needs the `ae-*` ids; text follows `<html lang>` (en/ru) live; dark tones only when the frame background is dark. When adding a guide for a mission, set its slug here. Test hook: `window.__aePreserve=true` before the script, then `__aeShow(i)`, `__aeSetP(p)`, `__aeDraw(ms)`; headless Firefox only captures the canvas after `toDataURL()` into an `<img>`.
- `AGENTS.md` — the full "virtual expert team" charter (engineering, science, content, workflow roles). Read it before nontrivial changes; it has authority over role-specific conventions this file doesn't restate.
- `docs/`, `time philosophy/` + `time-philosophy/` (duplicate-looking dirs — check both before assuming one is dead) — secondary content areas.
- A few stray root files look like abandoned duplicates/typos (`build-your-own-cubsat.html`, `ISSandMir.html`, `lagrange-points.html`, `unfold-james-webb.html` vs. their differently-named full versions) — don't edit these without checking `pages.json`/`sitemap.xml` for which one is actually live.

## Conventions
- Single-file-per-article pattern; keep bilingual EN/RU markup structurally parallel so shared CSS/JS keeps working for both.
- No framework/build-step creep without explicit sign-off (see AGENTS.md, Principal Frontend Engineer role).
- WCAG 2.2 AA+ accessibility, responsive/fluid layout, progressive enhancement.
- Never use Russian in code/UI/docs unless the task explicitly calls for it (bilingual EN/RU *content* pages are the one deliberate exception the site's premise calls for).

## Share pictures (og:image)
Added 2026-10-28. Every public page has a 1200×630 share picture at `og/<canonical path>.jpg` (`og/index.jpg` for the front page) and the tags `og:image` (+ width, height, alt), `twitter:card` = `summary_large_image` and `twitter:image`. `_tools/assemble.py` writes the tags for generated guides; hand-authored guides carry them directly, placed after the page's other og:/twitter: tags. The pictures are drawn by `engine/og_cards.py` in the followorbounce.github.io repo (one card template, this site's own palette and type, `og/manifest.json` = a hash per card so unchanged cards are skipped). After adding or renaming a page, or changing a title or description, run `python3 engine/og_cards.py aerospace` from that repo; it renders new cards, adds missing tags and deletes cards of pages that went away. `--check` lists pages without tags.
